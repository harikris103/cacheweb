⚡ Caching Explained

A quick seminar: what it is, why it’s fast, and where you already use it every day.

What is Caching?

Caching means keeping a copy of data you use often in a fast place, so you don’t repeat slow work again and again.

🧊 Cache = Fridge
Masala is already there. Takes 5 seconds. Fast and close, but small.
🛒 Database = Market
Walk to the shop, queue, come back. Takes 30 minutes. Big but slow.
TermMeaning
Cache HitData found in cache → instant answer
Cache MissNot found → fetch from database, then save a copy
TTLTime‑To‑Live: the copy auto‑expires after some time
EvictionMemory full → remove the least recently used data (LRU)
InvalidationSource data changed → delete the old copy

Speed difference

⚡ Cache (RAM)~1 ms
🗄️ Database~100–1500 ms
💡 The first visitor pays the price (miss). Everyone after them gets the fast path (hit) until the TTL expires.

Where you already use caching

🌐

Web browser

Cached: images, CSS, JS of a site.

Why: 2nd visit loads without re‑downloading.

Revisit = instant
🎬

Netflix / YouTube (CDN)

Cached: popular videos on servers near your city.

Why: no need to stream from the US each time.

Less buffering
📸

Instagram / X feed

Cached: your timeline, like counts, profiles in Redis/Memcached.

Why: millions open the app at once.

Millions of reads
🍔

Swiggy / Zomato

Cached: restaurant menus and ratings.

Why: menus rarely change, but are viewed constantly.

Menus load fast
🛍️

Flipkart / Amazon sale

Cached: product pages, prices, “people viewing” counts.

Why: Big Billion Days traffic would crash the DB.

Survives sale rush
🚆

IRCTC / ticket sites

Cached: train lists, station names, static pages.

Why: keeps the DB free for real bookings.

DB protected
🔎

Google Search

Cached: results for popular queries.

Why: thousands search the same thing daily.

Results in ms
📡

DNS

Cached: google.com → IP address, in phone and router.

Why: skip the lookup every click.

Faster page start

Login, OTP & UPI

Security + speed

Caching happens at many layers

A request passes through several caches before it ever reaches the database:

📱 Browser cache images, files on your device
🌍 CDN cache Cloudflare, Akamai, near your city
🖥️ Application cache Redis / Memcached
🗃️ Database cache query results, buffer pool
💾 Database on disk the slowest, the source of truth
⚠️ Famous joke: “There are only two hard things in computer science: cache invalidation and naming things.” Stale data is the cost of speed.

Key Takeaways

  1. Cache = a fast copy of slow data.
  2. Hit is fast, miss is slow, and the first request is always a miss.
  3. Always set a TTL so old data cleans itself up.
  4. When the source data changes, invalidate the cache.
  5. Redis, the most popular app cache, is used by Twitter, Instagram, Swiggy and more.
Cache‑aside logic in 4 lines
1. Look in cache → found? return it (HIT)
2. Not found? Ask the database (MISS)
3. Save the answer in cache with a TTL
4. Return the answer
